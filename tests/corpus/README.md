# End-to-end corpus

Small files that reproduce real-world CSV problems, each run through the command line with the options in `cases.json`. `tests/test_corpus.py` compares the JSON report of every case with `expected/<name>.json`, byte for byte, together with the exit code.

| File | What it exercises |
|---|---|
| `es_excel_cp1252.csv` | Spanish spreadsheet export: cp1252 with CRLF line ends, `;` separators, amounts like `1.234,56` and `12.345.678,9`, `s/d` gaps (one of them padded, `" s/d "`, which must count as missing and not as untrimmed), values with surrounding spaces, one exact duplicate row. Used twice: plain, and through every kind of quality gate. |
| `utf8_bom_events.csv` | UTF-8 with a byte order mark, ISO 8601 date-times with different offsets (the range compares instants), booleans in two cases, a header name with surrounding spaces. Used twice: plain, and through `--range` with date-time bounds in UTC that the events meet only when compared as instants (`08:00-04:00` is the 12:00 UTC lower bound). |
| `tab_quoted.tsv` | Tab separated, with quoted fields that contain a newline, a comma and a tab, and an exact duplicate record. |
| `ports_pipe.csv.gz` | Pipe separated and gzip-compressed; both are detected from the content. |
| `erp_day_first.csv` | ERP export with day-first dates (`5/1/2026`, `02/01/2026 8:15`) read with `--date-order dmy`, ISO values in the same columns, grouped weights, and an impossible due date (`30/02/2026`) that keeps the column as text, is named in the type hint and fails `--require-type`. Also checked for freshness with `--max-age` on a fixed clock and `--utc-offset=-04:00`: the last dispatch is 3 days 4 hours old and fails a 2-day limit, while the last issue date, which counts until the end of its day, passes a 3-day one. |
| `excel_es_booleans.csv` | Spanish Excel "CSV UTF-8" export: BOM, CRLF, `;`, `VERDADERO`/`FALSO` and `Sí`/`No` flags in several cases read with `--bool-words`, day-first dates and grouped amounts; one `Pendiente` keeps a flag column as text, is named in the type hint and fails `--require-type`. |
| `excel_sep_hint.csv` | Excel export in cp1252 that starts with a `sep=;` line: with `--delimiter auto` the line is skipped and the declared semicolon is used; with the default comma the tool stops with exit code 7 and names the declared delimiter (the second case stores that error message). |
| `py_invoices_affixes.csv` | Invoice export with amounts in guaraníes and dollars (`Gs. 150.000`, `US$ 25,50`), weights in `kg` with one in `lb`, and `%` discounts, read with `--number-affix`: the amounts become numbers and the per-column affix counts expose the mixed currencies and units; `a convenir` keeps the discount as text. Used twice: plain, and with `--max-affixes`, where the mixed amounts and weights fail. |
| `erp_balances_sap.csv` | ERP trial balance with negative balances written with a trailing minus (`84.300,50-`) and in parentheses (`(9.870,00)`), read with `--accounting-negatives`; debits minus credits equal the sum of the balances, which checks the signs. Used twice: plain, and through `--range` checks. |
| `py_invoices_next_day.csv` | The next export of the same invoices, compared with `expected/py_invoices_affixes.json` through `--baseline` and `--fail-on-schema-change`: a dropped column, a new one, an amount that turned the column into text and more blank weights. Used three times: with `--fail-on-schema-change`; with the drift gates `--max-row-drop` (passes: there are more rows) and `--max-missing-increase` (fails: `Peso` went from 12.5% to 44.44% missing); and with `--max-missing-increase 0` plus `--max-missing-increase-column Peso=35` (passes: the other columns lost no values and `Peso` rose 31.94 points, within its own limit). |
| `courier_shipments.csv` | Courier export (`;`, day-first dates, decimal comma) where tracking codes repeat in rows that differ in the order, date or status: a parcel sent three times and a code written once with surrounding spaces. No two rows are equal, so `--max-duplicates 0` passes, while `--unique Guía` fails with 3 repeated cells and `--unique Pedido` passes; the `s/d` and empty codes are missing values, not repeats. Also checked with `--allowed-values` against the statuses a consumer handles (`Entregado`, `En tránsito`, `Pendiente`): the one returned parcel (`Devuelto`) fails it. |
| `ar_customers.csv` | Customer master export of an Argentine distributor (`;`, decimal comma, `.` thousands) checked for the format of its codes with `--pattern`: a tax id (CUIT) written without dashes and one with spaces fail `\d{2}-\d{8}-\d`, and two postal codes cut to five characters (`C1428`, `X5000`) fail `\d{4}\|[A-Z]\d{4}[A-Z]{3}`, which accepts both the old four-digit codes and the full eight-character ones. The tax id padded with spaces is stripped and passes; the `s/d` and empty cells are missing values and are not checked. |
| `erp_invoice_lines.csv` | ERP invoice lines (`;`, decimal comma) whose invoice numbers restart in each branch, so a line is identified by branch, invoice and line number. No two rows are equal and every column repeats on its own, so neither `--max-duplicates 0` nor `--unique` can check it. `--unique-key Factura,Línea` fails with 5 rows, because two branches share numbers; `--unique-key Sucursal,Factura,Línea` finds the one line exported twice with another amount (its invoice number padded with spaces). The row without a line number is skipped by both keys. |
| `stock_counts_week1.csv`, `stock_counts_week2.csv` | Two weekly stock counts of a distributor (`;`, decimal comma). In the second, bulk items counted in kilos (`12,5`) turn `Cantidad` from int into float, the counts carry a time (`Fecha conteo` date -> datetime) and lot codes such as `L-0042` turn `Lote` into text. The first is profiled plain and is the baseline of the second, which is used three times: with `--fail-on-schema-change` (3 changes fail); with `--allow-type-change Cantidad=int:float` and `date:datetime`, which tolerate the two widenings while `Lote` int -> string still fails; and with the same rules and `--columns` leaving `Lote` out, where the gate passes and lists what it allowed. The first is also profiled with `--record-time` on a fixed clock (`SOURCE_DATE_EPOCH`), and that stamped report is the baseline of `--max-baseline-age 8d`: a week later the baseline is 6 days 14 hours old and passes, two weeks later (13 days 14 hours) it fails; the unstamped report of the first count fails the same gate and says how to stamp it. The first count is also checked with `--max-age` and no `--utc-offset`: its dates have no offset, so the check fails and says how to give one instead of guessing a time zone. |
| `stock_counts_week3.csv` | The same weekly count three weeks later, after an ERP upgrade: the export adds a `Unidad` column and lot codes moved to another export (`Lote` is gone); quantities and dates have the types of the first count again. Compared with the first count three times: with `--fail-on-schema-change` (2 changes fail); with `--allow-added-column Unidad`, which tolerates the new column while the removed `Lote` still fails; and with `--allow-removed-column Lote` as well, where the gate passes, lists what it allowed, and the comparison still shows both columns. |
| `erp_header_only.csv` | The export of an ERP job that failed half-way: only the header line, with semicolons and CRLF. The delimiter is still detected and every column is reported with 0 values; `--max-missing` and `--require-columns` pass, since nothing in it is missing, and `--min-rows 1` fails with 0 data rows. |
| `erp_sales_titles.csv` | ERP sales export in cp1252 with CRLF that starts with three title lines (report name, period, issue time) and a blank line before the header, read with `--skip-lines 4`: the semicolon is detected on the lines after them, day-first dates and `1.234,56` amounts are typed, and an `s/d` customer and amount are missing values. Used three times: with `--skip-lines 4`, `--min-rows 1` and `--require-columns`, which pass; without `--skip-lines`, where `--delimiter auto` stops with exit code 7 and suggests `--skip-lines 3` (the blank line is skipped anyway); and with `--delimiter ";"`, where the first title is a one-field header, the real header fails as a ragged row at line 5 and the message suggests `--skip-lines 4`. |
| `erp_dispatch_footer.csv` | ERP dispatch export of a warehouse in cp1252 with CRLF: two title lines and a blank line before the header, and a footer after the seven dispatches (a blank line, a `Total despachado;;;;2.345,60` totals row with the header's width, a record count and a generated-by line). Used four times: with `--skip-lines 3` and `--skip-footer 3`, where the semicolon is detected without the footer and `--unique`, `--require-type`, `--range Kilos=0:1500` and `--allowed-values` pass; with `--skip-footer 2`, where the totals row is profiled as an eighth dispatch (its empty date and status are missing values) and its 2.345,60 kilos fail the range; without `--skip-footer`, where `--delimiter auto` stops with exit code 7 and suggests `--skip-footer 2` (the totals row has the header's width, so the message adds one for each totals row); and with `--delimiter ";"`, where the record count fails as a ragged row at line 14 and the message suggests dropping it and the line after it. |
| `excel_es_month_names.csv` | Spanish Excel export (`;`, CRLF, decimal comma, `.` thousands) whose order dates use Excel's `dd-mmm-aaaa` format in several cases (`28-sep-2026`, `30-Sep-2026`, `03-OCT-2026`, `5-octubre-2026`) and whose delivery times use dotted abbreviations, the Uruguayan `set.` and a 12-hour `2:45 p. m.`; one delivery is `s/d`. Used twice: with `--date-order dmy --month-names`, where both columns are typed (`date` and `datetime`) and `--require-type` and `--range` pass; and without `--month-names`, where both stay text and `--require-type` fails. |
| `mostly_typed.csv` | Stray values (`N/A`, `12a`, `pendiente`) that keep numeric and date columns as text; the type hints name them and `--require-type` fails. |

A case may set environment variables with `env`, such as `SOURCE_DATE_EPOCH` for a fixed clock; they are restored after the case runs.

Cases that end with an error (an exit code other than 0, or 8 for failed quality gates, which still print the report) store the message printed on stderr in `expected/<name>.txt` instead of a JSON report.

When a change to the tool is meant to alter a report, run `python scripts/update_corpus.py` and review the diff of `expected/` before committing: the diff is the change in behavior. `--check` only reports stale files.

The expected reports were checked by hand when the corpus was created (ranges, means, duplicate counts, type hints and failing checks), so they are a reference, not just a snapshot.
